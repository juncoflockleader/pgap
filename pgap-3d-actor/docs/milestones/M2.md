# M2 — Dog Parametric Library

Implementation plan for PRD §10 milestone **M2**. Builds on
[M1.md](M1.md). PRD wins on scope, DESIGN wins on detail, this doc wins on M2
sequencing.

## Goal

Turn the generic M1 quadruped into a **recognizable golden retriever** via a
breed/trait part library: ear/snout/tail variants plus extra detail primitives
(skull dome + stop, cheeks, nose, deep chest/brisket, neck ruff, hindquarters,
feathered tail). Tuned proportions ship as the reference golden-retriever spec.

**Exit (PRD §10):** a *recognizable dog* — a neutral viewer reads the rendered
output as a dog (validated by importing into the live UE editor and eyeballing
the thumbnail).

## In scope / deferred

- **In scope:** part library (data-driven extra SDF primitives), ear-style bone
  placement, golden-retriever reference proportions, geometry blend of
  bones + parts. Still deterministic.
- **Deferred:** animations (M3), UVs/textures (M4 — fur material is what finally
  sells "golden"), proof-lane PIE (M5), other breeds/archetypes (M6).

## Approach

Two layers, cleanly separated:

1. **Ears via the rig** (`skeleton.py`). `traits.ears` (`floppy`|`pointy`) sets the
   ear-bone droop direction + radius so the ear *is* a deforming bone capsule
   (floppy = fat flap hanging beside the cheek; pointy = thin upright). Skinning
   is unchanged — the ear geometry binds to its own ear bone.
2. **Detail via a part library** (`parts.py` + `archetypes/dog.py`). Non-bone
   detail primitives (capsules/spheres) positioned **relative to named bones**
   and sized **relative to bone radii**, so they track proportions + global scale
   automatically. They bind by proximity to the nearest bone (chest→spine,
   ruff→neck, feather→tail, haunch→thigh, skull→head) — no skinning changes.

`Primitive(a, b, radius_a, radius_b)` (a sphere is `a==b`). The geometry kernel
blends bone capsules **and** parts in one smooth-min field.

## Golden-retriever part set (`archetypes/dog.py`)

Skull dome + brow/stop (rounds the head, breaks forehead→muzzle), cheeks ×2,
rounded nose, deep brisket/chest, neck ruff, full hindquarters ×2, and an
underside tail plume when `traits.tail == feathered`. Variant tables for
`ears`/`snout`/`tail` keep it parametric.

## Stage / file changes

- `types.py` — add `Primitive`.
- `geometry.py` — refactor SDF to operate on a primitive list; `build_geometry`
  takes `parts`; grid bounds include parts; tune smooth-min `k`.
- `parts.py` — `build_parts(skel, spec)` dispatch by species.
- `archetypes/dog.py` — dog part builder + ear/snout/tail variant data.
- `skeleton.py` — ear-style placement + radii from `traits.ears`.
- `pipeline.py` — single `build_actor(spec, rng)` = skeleton→parts→geometry→skin,
  shared by CLI + tests (removes duplication/drift).
- `fixtures/dog_golden_retriever.json` — tuned reference spec.

## Determinism

Parts are analytic (no RNG). Mesh stays within budget (tune grid resolution /
`triBudget` once parts add surface). Determinism + validity tests extended to the
parts path via `pipeline.build_actor`.

## Exit checklist

- [ ] `build_actor` blends bones + dog parts; mesh single-component, watertight,
      within tri budget, weights still valid
- [ ] Imports into live UE → SkeletalMesh + Skeleton; thumbnail reads as a dog
      (floppy ears, muzzle, chest, feathered tail visible)
- [ ] Deterministic SHA across processes; all prior tests still pass
